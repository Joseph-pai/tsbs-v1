# 🚀 V3.1 短線過濾掃描更新總結

本次更新已成功完成短線過濾掃描（V3.1）的邏輯重構與介面調整，並已將代碼推送到 GitHub。本次修改嚴格遵循您的要求，確保未影響原有定點共振掃描與強化評分掃描的邏輯。

## 🎯 核心改動內容

### 1. 新增 API 與後端評分引擎
- **新增端點**：建立了 `/api/scan/short-term-v31/route.ts` 支援 GET（即時掃描）與 POST（歷史掃描）。
- **實作 V3.1 邏輯**：在 `scanner.ts` 中新增了 `scanShortTermV31()` 函數，精準實作了 4 大維度與新鮮度係數算法：
  - **Dim 1 (RS 雙軌制)**：支援正常/保守模式切換，判斷近期動能是否超越中期動能。
  - **Dim 2 (VSR)**：根據大盤位階（>1.5 或 >2.0）實行嚴格的爆量過濾（Hard Filter）。
  - **Dim 3 (K線品質)**：實體驗證與 20 日突破判斷。
  - **Dim 4 (法人共振)**：串接 FinMind 取得投信、外資資料，計算 A1/A2/A3 與 Logic B 族群共振。
  - **漲停保護與新鮮度**：對漲停標的給予保留分與溢價，並針對連漲天數（trend_days）施加動能打折係數。

### 2. 優化 API Token 消耗（FinMind）
- **延遲查詢機制**：在 `scanShortTermV31()` 中，前三大維度（RS、VSR、K線）皆使用免費的 Exchange API 計算。只有在前三維度總分超過 45 分的股票，才會去請求 FinMind 法人數據，這將省下約 96% 的 Token 消耗。
- **Redis 快取**：全面導入 Redis 快取機制，避免同日重複向外部 API 請求資料。

### 3. 前端介面調整 (`page.tsx`)
- **移除舊版選擇器**：移除了「短線大盤濾網模式（自動/寬鬆/中等/嚴格）」按鈕群組。
- **新增歷史日期多選 UI**：在原短線過濾按鈕上方，加入了從 Firebase `scan_history` 提取日期的快捷按鈕，支援單選或多選。
- **動態切換掃描模式**：
  - **選擇歷史日期**：自動收集該日期的所有股票代碼（`stockIds`），並向後端請求重新拉取「那天的實際歷史數據」進行重新評分。
  - **未選擇日期（空）**：點擊按鈕直接觸發「當日全市場即時掃描」。

## 🛡️ 程式碼與架構保護
- 所有的修改都完全獨立於 `scanShortTerm`、`scanOriginal` 等現有函數之外。
- `StockCard` 與原有的 `AnalysisResult` 介面完美相容，無須改動前端結果渲染邏輯即可自動套用 v3.1 的標籤與分數呈現。
