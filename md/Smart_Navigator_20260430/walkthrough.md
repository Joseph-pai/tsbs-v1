# Smart Navigator 修復與功能升級總結

本文件總結了針對「智能選股導航」功能的 500 錯誤修復，以及「真實換手率」計算功能的實作細節。

## 修改重點

1. **修復 500 API 呼叫上限錯誤**
   - **問題**：原先使用 `FinMind` 抓取近 200 天歷史資料，容易觸發免費版的呼叫頻率限制 (API 402)，導致後端回傳 500 錯誤。
   - **解決方案**：將 `/api/smart-navigator` 的底層資料抓取改為使用 `ExchangeClient.getStockHistory`。這會直接向證交所與櫃買中心抓取資料，**不佔用 API 配額**，大幅提升了穩定性。
   - **優化**：同時優化了 `ExchangeClient` 的穩定性，現在即使某個月份的資料暫時缺失，系統也會自動跳過並繼續抓取其他月份。

2. **實作「真實換手率 (Turnover Rate)」**
   - **新增模組 (`src/lib/shares.ts`)**：
     - 自動從證交所 (`t187ap03_L`) 與櫃買中心 (`t187ap03_O`) 的 Open API 獲取全台股公司的「實收資本額」與「發行總股數」。
     - 具備 **12 小時快取機制**，避免重複抓取造成延遲。
   - **計算邏輯升級**：
     - 現在能精準計算：`真實換手率 = (當日成交量 / 發行總股數) * 100%`。
     - **燈號判定更精準**：現在「綠燈」與「紅燈」的判定會參考真實換手率（例如換手率 > 5% 為熱絡，> 25% 為過熱爆量）。
     - **自動回退機制**：若萬一無法取得該股總股數，系統會自動切換回「與 5 日均量對比」的模式，確保功能不中斷。

3. **穩定性增強**
   - 修正了 `isTpexStock` 對熱門權值股（如 2330, 2317）的判定路徑，確保抓取正確的市場資料。

## 驗證結果
- 經測試股票 `2330` (台積電)：成功獲取發行總股數 `25,932,524,521`，計算出真實換手率約 `0.23%`，燈號顯示為黃燈（穩定持股），且不再出現 500 錯誤。
