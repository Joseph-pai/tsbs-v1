# 模擬交易功能實作計畫

## 目標
在現有系統中加入「模擬交易」功能，讓用戶可以輸入歷史買入紀錄，自動化驗證是否達到目標價，並計算最終獲利總金額。

## 修改範圍

### 1. 新增 `src/components/MockTradingModal.tsx`
建立一個新的獨立 Modal 元件（維持現有科技感與暗黑玻璃風格）。
**功能包含：**
- **動態表單列**：可透過「+」號連續新增多檔股票的模擬交易列。
- **欄位設計**：
  - `買入日期`：日期選擇器（預設為今日前一日）。
  - `股票代碼`：輸入代碼後，利用傳入的 `snapshot` 資料自動帶出 `股票名稱`。
  - `買入價格`：手動輸入數值。
  - `買入股數`：手動輸入數值（預設 1000 股）。
  - `停利目標`：下拉選單（手動輸入、+2%、+3%、+5%、+10% 等）。選擇 % 數時，根據「買入價格」自動計算「預計賣出價格」。
  - `預計賣出價格`：顯示數值，當「停利目標」為「手動」時可編輯。
- **回測引擎**：
  - 點擊「開始回測」後，系統會針對每一列發送 API 請求。
  - 使用既有的 `/api/backtest`，參數帶入 `fromDate=買入日期`、`toDate=今日`、`targetPrice=預計賣出價格`。
  - 若 `peakPrice >= targetPrice` 則判定為【賣出成功】。
- **獲利計算**：
  - 單筆獲利：` (預計賣出價格 - 買入價格) * 買入股數 `。
  - 顯示各檔股票的成功與否與單筆獲利，並在底部加總顯示「總獲利金額」。

### 2. 修改 `src/app/page.tsx`
- **狀態管理**：新增 `const [showMockTrading, setShowMockTrading] = useState(false);`
- **UI 按鈕**：在原本的「12H 預約賣出助手」按鈕旁，新增一個「模擬交易」按鈕。
- **元件引入**：在頁面中引入 `<MockTradingModal isOpen={showMockTrading} onClose={() => setShowMockTrading(false)} snapshot={snapshot} />`，並將現成的 `snapshot` 傳入供股票名稱自動對應。

## 安全性與不影響現有功能
- **完全獨立元件**：將邏輯全部封裝於 `MockTradingModal` 中，不會動到核心的 `runScan` 或是 `runBacktest`。
- **復用現有 API**：利用已穩定運作的 `/api/backtest` 進行歷史高點比對，無需新增複雜的後端路由，保證穩定性。

> [!NOTE]
> 這個計畫完全獨立新增功能，不會影響您目前正在使用的預約助手與選股掃描功能。
